AI-generated code is judged by whether it runs, and that standard is embarrassingly low. I’ve watched teams celebrate a feature because the demo worked, then spend three days untangling duplicate API calls, leaky abstractions, and error handling that only exists when the sun is friendly.

The pattern is brutally consistent: generated code optimizes for the visible path. If the input looks like the example, it performs beautifully. If reality arrives wearing different shoes—nulls, retries, stale data, timezone chaos, a user clicking twice—it improvises nonsense.

“Works” means the happy path passed once. That’s not quality; that’s a successful magic trick with the machinery still underneath. Good code has a shape you can reason about. It names things clearly, keeps boundaries honest, and fails in ways that tell you what happened. AI code often does none of this because the model optimized for plausibility, not maintainability.

The tell isn’t the amount of code. It’s whether a tired human can change it six months later without bargaining with a haunted flowchart.

AI-generated code that merely runs is unfinished work with better branding.
