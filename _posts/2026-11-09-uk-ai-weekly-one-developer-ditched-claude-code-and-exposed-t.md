# UK AI Weekly: One Developer Ditched Claude Code — and Exposed the Real AI Battle

A developer has switched their main coding harness from Claude Code to Pi, and the reasons are more revealing than another shiny AI demo. The complaint is not that Claude Code cannot write code. It is that the product keeps changing underneath users’ feet.

Caleb, writing on 21 September, points to a telling coincidence: just after deciding to leave, Anthropic announced support for `AGENTS.md`, the kind of shared instruction file the author wanted. “Too little, too late,” they wrote.

The deeper frustration involves consistency. Claude Code had released 244 versions this year, with more than three-quarters changing either the system prompt or tool descriptions. That sounds like rapid innovation, but it can also mean yesterday’s dependable workflow becomes today’s surprise. The author also reports that the VS Code integration could connect only one session at a time, while the official graphical interface had broken commands and tangled output from multiple agents.

Then there is overhead. The default Bash tool description runs to almost 3,000 tokens, including guidance for using Git and opening pull requests. The author’s view is blunt: models can already handle those tasks without quite so much hand-holding. Their move to Pi, an open-source coding harness, was driven by stability, minimalism and customisation. They even built an extension for handling multiple tabs in roughly 20 minutes.

This is not a British story, and the source does not identify a UK user, company or deployment. Its UK significance is more practical. Coding agents are becoming part of how software gets built here, but the choice of harness increasingly determines cost, workflow and how easily developers can inspect changes. For UK teams, portability and control may matter more than piling on enterprise features nobody asked for.

Regulation, meanwhile, does not care which harness a developer chooses. The UK still has no AI-specific statute or single AI regulator. Its approach remains principles-based and sector-led, consistent with the government’s pro-innovation AI Opportunities Action Plan. If coding agents process personal data in prompts, repositories or logs, the UK GDPR and Data (Use and Access) Act 2025 apply, with the ICO enforcing data-protection duties.

What this means is that AI development is shifting from the “which model is smartest?” argument to a less glamorous but potentially more important one: can developers understand, control and rely on the tool operating their code? Claude Code’s feature race illustrates how quickly a useful assistant can become frustrating software. Pi’s appeal shows the market increasingly rewards restraint, transparency and the freedom to change things.

The UK takeaway is simple: AI policy cannot make unstable products stable, and the next coding-tool battle may be won by the platform that gets out of the way.
